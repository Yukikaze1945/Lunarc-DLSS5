# Lunarc · 使用手册

[简体中文](user-guide.md) · [English](en/user-guide.md) · [日本語](ja/user-guide.md) · [Русский](ru/user-guide.md)

基于当前源码。安装版可能尚未包含最新功能；是否可用取决于显卡、驱动和运行库。

界面默认跟随系统语言，可在「软件设置 → 界面语言」中手动选择。

<a id="quickstart"></a>
## 首次使用

Lunarc 在 Windows 本机处理视频和图片。先装好运行环境，再添加你要用的效果；不需要一次下载所有模型。

1. 从 [GitHub Releases](https://github.com/Yukikaze1945/Lunarc-DLSS5/releases) 下载安装程序，安装并启动。
2. 按首次启动教程安装**基础运行环境**和**视频处理组件**。
3. 需要 DLSSNR 时，进入**运行与诊断 → DLSSNR 运行库**，下载或导入运行库，再选择“使用”。DLAA、VSR、VFG、TrueHDR 分别需要相应的 NVIDIA 组件。
4. 点击**导入**，或把本机视频、图片拖入工作台。
5. 先启用一项效果，查看原图与结果。确认后再增加其他阶段。
6. 视频进入**导出与队列**，图片使用右上角的**导出图片**。

安装版无需自行准备 Python、Node.js 或 CUDA Toolkit。RAFT 和独立图片模型需要额外的 AI 模型运行环境；不使用这些模型时不必安装。

<a id="pipeline"></a>
## 渲染顺序与开关

工作台右侧的渲染链**从上到下**执行。后一项接收前一项的输出，调整位置会改变处理结果，也可能改变耗时和显存需求。

| 操作 | 作用 |
| --- | --- |
| 拖动左侧手柄 | 调整阶段顺序。输入框和参数滑块不触发卡片拖动。 |
| 上下箭头 | 将一项向上或向下移动一位。 |
| 眼睛按钮 | 暂时停用这一项，保留其参数和位置。再次点击恢复。 |
| ＋ / − | 展开或收起参数。折叠不会停用效果。 |
| 移除 | 从当前链路移除该阶段。 |

DLAA、DLSSNR、RTX VSR、TrueHDR 和 NVIDIA VFG 都使用这套顺序。VSR 可以重复添加，每张卡片保存自己的模式、档位、强度和输出尺寸。

例如，VFG 后面的模型会继续处理生成帧，因此同一套模型放在插帧前后，工作量可能不同。这里没有对所有素材都合适的固定顺序。

[试一下渲染链排序演示 ↗](https://lunarc-workbench.defaddg-9590.chatgpt.site/#render-order)

<a id="nr"></a>
## DLSSNR 与多层处理

DLSSNR 是神经重建阶段。先调整模型本身的参数，再决定是否使用额外的残差、色彩和时间控制。

| 参数 | 含义 |
| --- | --- |
| NR 强度 | 控制模型修正画面的强度。数值更大表示修正更强，不代表所有素材都更好。 |
| 局部色调强度 | 调整模型的局部色调修正，不是全局曝光，也不是 HDR 显示映射。 |
| 局部结构强度 | 调整纹理和局部结构修正。 |
| 皮肤结构强度 | 调整模型对皮肤结构的修正，与局部结构独立。 |
| 自动遮罩 | 使用模型的自动遮罩；与手动区域保护分别控制。 |
| NR 界面修正 | 请求模型修正文字和界面区域，不能保证识别所有字幕。 |
| 画面风格 | 默认、自然、电影三个选项。建议用同一帧对比实际变化。 |

### 单层、双层与三层

**顺序处理**时，第二层继续处理第一层，第三层继续处理第二层。通过“调整本层参数”分别设置各层，避免把第一层的参数误当成整条链的公共参数。

**多尺度数据一致性融合**是另一条实验性路线：各尺度结果通过求解器融合，与前述逐层继续处理不同。其层尺寸、权重和求解参数会影响结果及资源占用，不适合仅凭层数判断画质。

### 工作分辨率与导出尺寸

工作缩放决定模型处理的工作尺寸。降低工作缩放会影响处理阶段，不能当作单纯缩小预览窗口。导出页的分辨率则决定最终文件尺寸；两者应分别检查。

<a id="dlaa"></a>
## DLAA 模型

在 DLAA 卡片中选择模型预设。当前界面提供**默认、J、K、L、M**以及**E / F 旧版兼容选项**。

- 默认：由运行库决定。
- K：项目说明中的 DLAA 推荐预设，可以作为比较起点。
- J、L、M：按素材对比细线、文字与运动边缘。
- E、F：旧版兼容提示，当前运行库可能替换它们。

这些是模型提示，不是视频编码的 Profile，也不是 VSR 档位；驱动或运行库仍可能覆盖提示。模型切换可能重新加载会话，首次更新通常更慢。

<a id="vsr"></a>
## RTX VSR

VSR 的处理模式、质量档位、效果强度和输出尺寸是独立设置。先选模式，再看该模式允许调整哪些项目。

| 模式 | 用途与输出 |
| --- | --- |
| 标准超分辨率 | 常规视频放大，按倍率或目标分辨率输出。 |
| 高码率超分辨率 | 用于压缩损失较少的素材，仍执行超分辨率。 |
| 流媒体超分辨率 | 需要支持该模式的显卡与运行库；当前要求 RTX 30 系及更新架构。 |
| 降噪 | 保持输入尺寸；增强过强可能抹平细节。 |
| 去模糊 | 保持输入尺寸；可能同时放大噪声。 |
| 双三次缩放 | 普通缩放，不使用 AI 模型。 |

### 档位与强度

质量档位为**低、中、高、极高**。流媒体模式只提供**中、极高**。效果强度可以保留运行库默认值，也可自定义为 0–100%。更高档位的速度、显存和效果取决于素材与硬件。

### 输出尺寸

**按倍率**提供 2×、4×和自定义。当前超分辨率单层倍率大于 1、最多 4 倍；输出保持比例并对齐偶数。**按分辨率**可选预设或自定义宽高，仍须满足引擎的比例和单轴倍率约束。

多张 VSR 卡片按顺序累计尺寸。最终导出选择“素材分辨率”时，即使链路已经放大，也会在保存前缩回原尺寸；要保留链路尺寸，选择“渲染链输出”。

<a id="truehdr"></a>
## TrueHDR 与色彩

TrueHDR 将 SDR 转为 HDR10，需要 VFX SDK Core 和 TrueHDR 特效模块。卡片可调整**对比度、饱和度、中灰亮度、目标峰值亮度**，并开关 **AI 去色带**。

| 参数 | 范围 |
| --- | --- |
| 对比度 / 饱和度 | 0–200，默认 100。 |
| 中灰亮度 | 10–100，默认 50。 |
| 目标峰值 | 400–2000 nit，默认 650 nit。 |
| AI 去色带 | 默认开启，可单独关闭。 |

HDR10 原片也可进入 TrueHDR：程序在该阶段前先映射为 SDR，再生成新的 HDR 画面。这会重新解释亮度与色彩，**不是原 HDR 的无损往返**。

TrueHDR 接口接收 RGBA8 SDR，因此即使原素材为 SDR 10-bit，也不能把这一项称为全程 10-bit 无损处理。HDR10 路径属于实验性功能；HLG、HDR10+、Dolby Vision 不在本手册所述的支持范围。

### 为什么预览和显示器效果不同？

Windows 桌面版的视频预览和启用 TrueHDR 的图片预览支持原生 FP16/scRGB。显示器和 Windows HDR 都启用时可呈现 HDR；未启用时会映射为 SDR。文件对比页、普通图片导出以及本宣传站使用 SDR 映射，不能代表 HDR 显示器上的实际峰值亮度。

<a id="flow"></a>
## 光流引导

光流用于重建阶段的运动引导。它和 NVIDIA VFG 不是同一个功能；VFG 使用自己的帧生成流程，不需要你为它单独计算 RAFT 光流。

| 引擎 | 设置 |
| --- | --- |
| NVIDIA NVOF | 使用 NVIDIA 光流接口，质量选项按当前引擎提供的预设显示。 |
| AMD FidelityFX Optical Flow | 性能 / 质量两个选项，分别采用半分辨率和全分辨率分析；不会因此降低主画面尺寸。 |
| RAFT-Large | 分析长边上限为 512 / 720 / 1080，迭代次数可以独立调整，需要额外的 PyTorch/CUDA 与模型。 |

RAFT 默认的速度、均衡、质量组合分别为**512 / 4 次、720 / 6 次、1080 / 12 次**；下方独立设置优先。分析尺寸只影响运动估计，不改变主画面的处理分辨率。更高尺寸和迭代数通常带来更多计算量，效果仍需查看实际运动区域。

<a id="quality"></a>
## 画质与时间稳定

后处理控制的是**模型结果相对原图的修正**。它不等于直接对整张画面做全局调色，也不能与 NR 强度混为一谈。

| 控制项 | 含义 |
| --- | --- |
| 总强度 / 残差强度 | 缩放模型与原图之间的修正；与模型内部的 NR 强度分别生效。 |
| 明度 / 色度强度 | 分别调整明度与色度修正。色度为 0 时保留原片色度，为 1 时保留模型的色度变化。 |
| 低频 / 高频强度 | 分别控制大尺度变化以及细节、纹理修正。 |
| 色相 / 暗部 / 高光保护 | 抑制对应区域或方向上的修正；0 表示关闭保护。 |
| 软压缩 | 减弱过大的修正，保留修正的正负方向。 |
| 区域保护 | 用矩形或椭圆减少指定区域的修正，可羽化边缘；与模型自动遮罩独立。 |

### 时间稳定与镜头检测

静态低频累积只在源画面局部稳定时混合历史残差，不是光流重投影。拖动、切换素材或场景变化会重置历史。单独开启镜头检测时不保留全尺寸时间历史。

调试显示会把残差或保护权重当作输出画面，可能同时影响 GPU 导出。正式导出前应关闭调试视图。

<a id="preview"></a>

载入后先显示原素材，拖动视频时间轴也可查看原片，不加载效果模型。此时的 HDR 原片缩略图采用 SDR 显示映射。先设置渲染链，再点击预览上方的 **开启渲染**。视频可选择 **实时渲染** 或 **预渲染**；后者提供 5 帧、10 帧、0.5 秒、1 秒、2 秒、3 秒、5 秒，从当前帧开始并在片尾截断。完成后点击 **回看结果** 或缓存绿条，在视频对比页检查。短片段预渲染不会改变导出选区，修改参数也不会自动重新预渲染。停止实时渲染会等待当前帧结束并释放预览显存。切换素材、重开软件或后端恢复后，需要重新手动开启。
## 预览与选区

工作台支持原图、增强、中央对比和双画面。中央分界线直接重绘已有 GPU 画面，不会因拖动对比线而重新运行模型；改变模型参数则仍可能需要重新处理。

### 先渲染一小段

1. 载入视频，启用时间轴下方的**选区导出**。
2. 拖动两个边界，或输入起始、结束帧。两个边界都可以用于定位画面。
3. 用**预渲染选区**生成一段真正的编码视频，再回看最终效果。
4. 完成且仍匹配当前素材和参数的区间显示**绿条**，点击绿条或“回看结果”进入对比页。

修改素材、渲染参数或编码设置后，旧缓存不再标绿。预渲染占用同一个 GPU 导出队列，实时预览会暂停；关闭选区导出则恢复全片导出。

界面帧号从 1 开始，结束帧包含在选区内。按帧选择要求恒定帧率和连续时间戳；可变帧率、缺帧等不满足条件的输入会被拒绝。片段起点重置时域历史，边界附近可能与从全片起点连续处理的对应帧不同。

### 底栏数据怎么看？

- **显存**是整卡占用，包含其他程序，不是 Lunarc 独占用量。
- **渲染 FPS**由最近处理帧的耗时换算，初始化、定位和缓存都会影响它。
- **显示 FPS**是实际呈现速度，不是素材标称帧率。
- **阶段延迟**不是一套可以直接相加的 GPU 时间戳；缓存复用、融合、光流和显示应分别理解。

<a id="presets"></a>
## 预设管理

工作台右侧、渲染顺序上方提供预设选择和**保存预设**。先调整参数，再命名保存；同名保存会替换旧预设。

预设管理页列出保存的预设。展开后查看相对默认值改变了哪些项目、原值、保存值和改动幅度。例如 NR 强度从 1.00 变为 0.70，显示差值 −0.30 和 −30%。

- 默认值为零时只显示差值，不计算百分比。
- 开关、风格和渲染顺序按选项变化显示，不给出无意义的百分比。
- 第二、第三层的改动分别记录。
- 应用预设后又修改参数，选择框显示“当前参数”。
- 支持 JSON 导入和导出，用于备份与迁移。

[试一下预设差异演示 ↗](https://lunarc-workbench.defaddg-9590.chatgpt.site/#preset-demo)

<a id="images"></a>
## 图片与放大模型

可导入 PNG、JPEG、BMP、WebP、TIFF、AVIF、HEIC / HEIF 和 JXR（JPEG XR）。普通图片入口处理 8-bit SDR；完整标记的 BT.2020/PQ AVIF 和 scRGB HDR JXR（fixed/float）进入线性 FP16 主图。16-bit / 32-bit 整数 JXR 与其它高位深 SDR 输入会被明确拒绝；动画图片只处理第一帧。

### 单帧渲染、显存与结果缓存

导入图片后先显示原图，默认点击 **渲染一帧** 才运行效果。改参数不会自动重算；需要连续调参时打开 **实时渲染**，关闭后恢复手动单帧。已有计算完成后才处理最新请求，避免同时加载多套模型。

- **省显存（逐项处理）**为默认：按卡片顺序处理，每项结束将完整中间结果保存在内存，再释放该项 GPU 资源。SDR 使用 RGBA8，HDR 使用线性 FP16，不把中间结果压成预览图。传输和反复加载模型会增加耗时。
- **快速（全链路常驻）**保留模型和链路资源，适合连续调参，但显存需求更高。
- 分步释放针对链路卡片；单张卡片内部的多层 NR 算法不变。不会自动分块或降低精度，单项本身仍可能超出显存。

最多保留**本次和上一份**完整尺寸结果，放在内存而非保留两套推理链。第三次成功渲染后清理更早的结果，关闭后端会清空。用预览顶部的 **对比参考 → 上一份结果** 与本次结果比较；移动分界线不重新推理。不同尺寸会缩放到本次尺寸用于显示，各份结果仍保留自己的 SDR/HDR 解释，导出不受显示缩放影响。

### 查看图片

- **Alt + 滚轮**：以指针附近为中心缩放，范围 25%–800%。
- **左键拖动**：平移画面；放大后普通滚轮可上下查看。
- **双击**：恢复适配。

查看位置不影响导出尺寸，也不会因为缩放、平移或拖动分界线就重新运行模型。

### 独立放大模型

| 模型 | 当前接入规格 |
| --- | --- |
| IllustrationJaNai V3 | 4× DAT2，去噪 / 细节两个版本。 |
| AnimeSharp V4 | 2× RCAN 标准版。 |

模型需要 AI 模型运行环境、图片模型组件与单独的权重。支持官方来源下载和本地导入。默认整图 FP32；可选分块会影响上下文与边缘结果，不会在显存不足时偷偷启用。当前模型只接受 SDR 图片，应放在 TrueHDR 前。

### 保存图片

点击**导出图片**，默认使用 **已渲染结果（只转换格式）**：直接保存完整尺寸缓存，无需重新运行模型，可选择本次或同一素材的上一份结果。参数改变后，重新渲染，或明确勾选“导出上次结果（忽略之后的参数改动）”。也可改为 **重新渲染后导出**。PNG、JPEG、WebP、AVIF、HEIC 是否可选取决于已安装编码器。

**输出色彩**可以选择 SDR 或 HDR：

- **SDR · sRGB**：PNG、JPEG、WebP、AVIF、HEIC，输出 8-bit SDR；TrueHDR 结果会映射为 SDR。PNG 支持无损与透明度；JPEG 不透明，透明区域填白。WebP 质量 100 使用无损编码。
- **HDR · 10-bit PQ**：在渲染链中开启 TrueHDR 后，选择 AVIF 或 HEIC。直接使用处理后的 FP16/scRGB 结果，转换为 BT.2020 / PQ，保存 10-bit、全范围、4:4:4 图片，不经过 SDR 显示映射。AVIF 需要视频处理组件中的 10-bit libaom-av1 编码器与 AVIF 封装支持；HEIC 需要 pillow-heif / libheif 编码组件。格式是否可选由本机组件检测决定。

- **UHDR JPEG**：输出 `.jpg`，保存 Display-P3 SDR 基图与 HDR 增益图。普通 JPEG 查看器可显示基图，兼容增益图的查看器可恢复 HDR；不支持透明度。只在有 HDR 结果时可选。
- **JXL**：SDR 使用 8-bit sRGB；HDR 使用 16-bit BT.2020/PQ RGB，支持透明度。质量 100 为送入编码器的像素无损，不逆转此前色域转换和量化。

编码组件已独立放入应用运行环境，缺失时格式会禁用。JXL 的 8-bit sRGB 文件可再次导入；HDR JXL 入口尚未接入。UHDR JPEG 再导入只读取 SDR 基图。[组件与色彩细节](image-codecs.md)。

质量 100 不等于 HDR RGB 无损：色域边界与 10-bit 量化仍有限制。PQ 编码会裁剪 BT.2020 色域外的负值和高于 10000 nit 的分量，并在保存结果中记录计数，不自动调整曝光。不会添加未经测量的母版显示信息。

支持保留源图透明度；若当前 HDR 编码器不支持透明度，控件会禁用并注明。使用缓存时此页显示结果的 SDR 映射缩略图，重新渲染保存后仍可能显示原图；请用支持 HDR 的查看器检查保存文件。**HDR 图片重新导入仍未接入**，不要把此页缩略图当作保存结果的 HDR 显示。

静态图片不计算帧间光流或时间稳定，不执行 VFG，也不进入视频批量导出队列。

<a id="framegen"></a>
## NVIDIA VFG 插帧

VFG 位于渲染链中，可排序和单独停用。它用于**导出**，实时预览跳过插帧并保留素材帧率；想看最终运动效果，应预渲染一段后回看。

| 设置 | 用法 |
| --- | --- |
| NVIDIA VFG（固定） | 按原帧率的 2×–16×输出；5×–16×属于实验性倍率。 |
| NVIDIA VFG（动态） | 填写高于源帧率的目标帧率，例如 60、120 或 60000/1001，自动计算中间时间点。 |
| 质量 | 低、中、高，对应 VFG 模型模式，不是 RAFT 或 NVOF 的光流质量。 |
| 镜头切换检测 | 避免在切镜处跨镜头混合。关闭此项不会同时关闭其他阶段的镜头检测。 |

片尾没有未来帧时会明确保持末帧。动态模式按均匀时间网格输出，末端时长取整误差小于一张输出帧。非均匀源时间戳会被拒绝。

需要支持的 NVIDIA 显卡、VFX Core 和 VideoFrameGeneration 模块。插帧不会修复已经写进素材的重复帧或所有运动伪影，应检查实际输出。

<a id="export"></a>
## 视频导出与队列

### 最终分辨率

| 选项 | 最终结果 |
| --- | --- |
| 渲染链输出 | 使用整个渲染链处理后的尺寸。VSR 输出 8K，文件就按链路的 8K 尺寸保存。 |
| 素材分辨率 | 采用原素材尺寸，链路放大后会在保存前缩回。 |
| 指定分辨率 | 使用预设或自定义宽高。 |
| 倍率 | 按输入素材计算 ×2、×0.5 或自定义倍率。 |

只有最终尺寸与链路尺寸不一致时，才显示并执行**导出缩放算法**。最近邻、双线性、双三次、Lanczos 2 都作用于整条渲染链之后，包括生成帧。

### 10-bit 与 HDR 编码

当前原生 P010 入口支持以下组合，封装为 **MKV**：

| 编码器 | 输入 / 色彩 | Profile |
| --- | --- | --- |
| HEVC | SDR 10-bit / BT.709 | Main10 |
| HEVC | HDR10 / BT.2020、PQ | Main10 |
| AV1 | SDR 10-bit / BT.709 | Main，10-bit |
| AV1 | HDR10 / BT.2020、PQ | Main，10-bit |

AV1 的 10-bit 属于 Main，不能套用 HEVC 的 Main10 名称。控件按输入色彩、编码器和运行库限制可选项；硬件不支持时明确拒绝，不应期待自动降为 8-bit 或改用别的编码器。

音轨、字幕、章节、元数据和附件按导出选择及容器能力保留。源静态 HDR 元数据只在适用时保留；TrueHDR 重新生成画面后，不把旧母版信息冒充新结果的测量值。

### 管理队列

1. 设置输出目录、文件名和编码选项，点击**加入队列**。
2. 启动队列，查看进度、FPS 与预计剩余时间。
3. 运行中的任务先停止，再删除；待办、完成、取消或失败的任务可以移除。
4. 失败时打开诊断报告，保存错误与设置。修正后重新提交，不要反复重试同一个不合法请求。

<a id="runtime"></a>
## 运行库、显存与更新

### 组件按需安装

基础环境和视频处理组件是起点。仅使用原生光流、DLSSNR 与 GPU 解码编码时不需要 PyTorch；RAFT 和独立图片模型才需要 AI 模型环境与各自权重。

DLAA 默认检查本机 NGX 缓存；VSR、VFG、TrueHDR 查找对应 VFX 目录。找不到或版本不匹配时，在组件、运行与诊断或高级设置中配置实际目录。10-bit / HDR 特效要求支持相应接口的运行库。

### DLSSNR 版本管理

支持 DLL / ZIP 本地导入、可信目录、版本下载与独立缓存。导入时检查 SHA-256、Windows 数字签名、发布者、架构、产品与版本；切换版本前关闭旧预览会话。普通 DLSS 的 DLL 不能当作 DLSSNR 使用。

原版和已知社区构建会标记身份；其他第三方 DLL 也可手动导入并自动选择，同一文件只提示一次“未识别身份 DLL”，不要求确认。文件格式和哈希检查仍保留。新版提供 A/B 模型选择，第二、第三层可独立设置；切换时先关闭旧链路再重建，不自动改变旧预设。

运行库适用其自身许可。社区版本目录不是 NVIDIA 官方发布目录；签名通过也不等于每个显卡、分辨率和 HDR 组合都兼容。导出期间不能切换或移除正在使用的运行库。

### 释放预览显存

点击工作台的**释放预览显存**，会暂停播放、等待当前帧结束并卸载预览资源。参数与磁盘模型不删除；调整参数也不会自动重载，点击**恢复预览**后重新加载。

显存紧张且更换模型、尺寸、来源或链路时，程序会先完整释放旧预览。保护不自动降低精度、分辨率或改用分块；SDK 内部峰值无法完整预估，仍可能发生显存不足。导出期间不能用这个按钮释放导出资源。

### 更新

进入**关于 Lunarc → 软件更新**检查和下载，退出程序后运行新版安装程序。组件与模型通常独立于主程序保存；更新后仍应核对运行环境检测结果。

<a id="troubleshooting"></a>
## 常见问题与限制

### 拖入图片后为什么没有图片放大卡片？

确认载入的是图片而不是视频，并检查当前安装版本。图片模型入口、运行环境、组件和权重分别准备；仅有模型名称不代表已经下载权重。较新功能可能先在源码版提供。

### VSR 放大后导出仍是原分辨率？

检查导出分辨率是否选成“素材分辨率”。选择“渲染链输出”保留链路尺寸；指定尺寸会在保存前执行最后一次缩放。

### TrueHDR 预览发白、过亮？

先确认是工作台原生 HDR 显示，还是已映射的 SDR 对比 / 网页图片，再检查 Windows HDR 状态。不要用普通 SDR 图片直接判断 HDR 峰值亮度。

### 打开 VFG，预览帧率为什么不变？

实时预览跳过 VFG。请用“预渲染选区”或导出短片检查插帧结果；底栏的渲染速度也不是文件最终帧率。

### 更换模型就显存不足，应该怎么处理？

先释放预览显存，再切换并恢复预览。减少同时运行的其他 GPU 程序，检查放大后的实际尺寸与模型层数。是否降低精度、分辨率或启用分块，应由你根据速度与画质取舍决定。

### GPU 已被驱动重置，继续点预览可以恢复吗？

设备重置后旧资源不再可靠。等待程序的后端恢复流程结束；仍不能恢复时，完整退出工作台与后端后重启。保存失败报告，不要把同一设备失效后的重复报错当成多个独立故障。

### 哪些功能仍然是实验性的？

HDR10、多尺度数据一致性融合和 VFG 5×–16×包含实验性实现。HLG、HDR10+、Dolby Vision、不受支持的编码器 / 容器组合不属于这里的支持范围。没有承诺在任意显卡上实时处理 4K 120 fps。

更详细的构建与验证记录见 [项目文档](https://github.com/Yukikaze1945/Lunarc-DLSS5#05--文档)。本站交互演示只展示操作方式，不运行模型、不修改你的本机设置。
