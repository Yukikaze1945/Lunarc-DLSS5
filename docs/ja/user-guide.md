# Lunarc · 操作マニュアル

[简体中文](../user-guide.md) · [English](../en/user-guide.md) · [日本語](../ja/user-guide.md) · [Русский](../ru/user-guide.md)

現在のソースに基づきます。公開インストーラーには未搭載の機能があります。利用可否は GPU・ドライバー・ランタイム次第です。

表示言語はシステムに合わせて自動選択されます。「ソフトウェア設定 → 表示言語」で変更できます。

<a id="quickstart"></a>
## はじめに

Lunarc は Windows 上で動画と画像をローカル処理します。最初に実行環境を整え、必要なエフェクトを追加してください。すべてのモデルを一度にダウンロードする必要はありません。

1. [GitHub Releases](https://github.com/Yukikaze1945/Lunarc-DLSS5/releases) からインストーラーを入手し、インストールして起動します。
2. 初回チュートリアルに従い、**基本実行環境**と**動画処理コンポーネント**をインストールします。
3. DLSSNR を使う場合は、**実行環境と診断 → DLSSNR ランタイム**でライブラリをダウンロードまたはインポートし、使用する版を選びます。DLAA、VSR、VFG、TrueHDR にもそれぞれ対応する NVIDIA コンポーネントが必要です。
4. **インポート**をクリックするか、ローカルの動画・画像をワークベンチへドラッグします。
5. まず一つのエフェクトを有効にし、元映像と比較します。結果を確認してから処理を追加してください。
6. 動画は**書き出しとキュー**へ進み、画像は右上の**画像を書き出し**を使います。

インストール版では Python、Node.js、CUDA Toolkit を別途用意する必要はありません。RAFT と専用画像モデルには追加の AI モデル実行環境が必要ですが、使わない場合は不要です。

<a id="pipeline"></a>
## 処理順序と有効・無効

右側の処理チェーンは**上から下**へ実行され、各段階は直前の出力を受け取ります。順序を変えると、結果だけでなく処理時間やメモリ使用量も変わる場合があります。

| 操作 | 動作 |
| --- | --- |
| 左のドラッグハンドル | 処理順序を変更します。入力欄やパラメータースライダーではカードのドラッグを開始しません。 |
| 上下の矢印 | 一つ上、または一つ下へ移動します。 |
| 目のボタン | 設定と位置を残したまま一時的に無効化します。再クリックで復帰します。 |
| ＋ / − | パラメーターを展開・折りたたみます。折りたたんでも効果は無効になりません。 |
| 削除 | 現在のチェーンからその処理を取り除きます。 |

DLAA、DLSSNR、RTX VSR、TrueHDR、NVIDIA VFG はすべてこの順序に従います。VSR は複数追加でき、各カードのモード、品質、強度、出力サイズを個別に保存します。

VFG より後ろのモデルは生成フレームも処理するため、同じモデルでも配置によって処理量が変わります。すべての素材に適した固定順序はありません。

[処理順序のデモを試す ↗](https://lunarc-workbench.defaddg-9590.chatgpt.site/ja/#render-order)

<a id="nr"></a>
## DLSSNR と多層処理

DLSSNR はニューラル再構成の段階です。まずモデル自体のパラメーターを調整し、その後で残差、色、時間方向の制御を使うか判断してください。

| パラメーター | 意味 |
| --- | --- |
| NR 強度 | モデルによる補正の強さです。値が高いほど補正は強くなりますが、必ず画質が向上するわけではありません。 |
| ローカルトーン強度 | モデルの局所的なトーン補正です。全体の露出や HDR 表示用トーンマッピングとは異なります。 |
| 局所構造強度 | テクスチャーや局所構造の補正を調整します。 |
| 肌の構造強度 | 肌の構造補正を、局所構造とは独立して調整します。 |
| 自動マスク | モデルの自動マスクを使います。手動の領域保護とは別の設定です。 |
| NR UI 補正 | 文字や UI 領域の補正を要求しますが、すべての字幕を認識できる保証はありません。 |
| 画面スタイル | デフォルト、ナチュラル、シネマの三つです。同じフレームで実際の変化を比較してください。 |

### 単層・2 層・3 層

**順次処理**では、第 2 層が第 1 層の出力を、第 3 層が第 2 層の出力を処理します。「この層のパラメーターを調整」から個別に設定してください。第 1 層の設定はチェーン全体の共通設定ではありません。

**マルチスケール・データ整合性融合**は別の実験的な処理方式です。異なるスケールの結果をソルバーで統合するため、一層ずつ順番に処理する方式とは異なります。層のサイズ、重み、求解パラメーターが画質やリソース使用量に影響し、層数だけでは品質を判断できません。

### 作業解像度と書き出しサイズ

作業スケールは処理段階の寸法を変えます。プレビューウィンドウだけを縮小する設定ではありません。書き出しページの解像度は最終ファイルの画素数を決めるため、別々に確認してください。

<a id="dlaa"></a>
## DLAA モデル

DLAA カードでモデルプリセットを選びます。現在は**デフォルト、J、K、L、M**と、旧版互換用の**E / F**を選択できます。

- デフォルト：ランタイムに選択を任せます。
- K：プロジェクトで DLAA の比較の出発点として推奨しているプリセットです。
- J、L、M：細線、文字、動く輪郭を素材ごとに比較してください。
- E、F：旧版互換のヒントです。現行ランタイムでは別のものに置き換えられる場合があります。

これらはモデルへのヒントであり、エンコードの Profile や VSR の品質段階ではありません。ドライバーやランタイムが上書きする可能性もあります。モデルの切り替えでセッションが再読み込みされると、最初の更新は遅くなる場合があります。

<a id="vsr"></a>
## RTX VSR

処理モード、品質、効果強度、出力サイズは独立しています。先にモードを選び、そのモードで使える設定を確認してください。

| モード | 用途と出力 |
| --- | --- |
| 標準超解像 | 一般的な動画拡大です。倍率または目標解像度を指定します。 |
| 高ビットレート超解像 | 圧縮による劣化が比較的少ない素材向けの超解像です。 |
| ストリーミング超解像 | 対応 GPU とランタイムが必要です。現在は RTX 30 シリーズ以降を要求します。 |
| ノイズ除去 | 入力サイズを維持します。強すぎると細部が失われる場合があります。 |
| ぼけ除去 | 入力サイズを維持します。ノイズも強調する場合があります。 |
| バイキュービック拡大 | AI モデルを使わない通常のリサイズです。 |

### 品質と強度

品質は**低、中、高、最高**の 4 段階です。ストリーミングモードでは**中、最高**のみ選べます。効果強度はランタイムのデフォルトを維持するか、0–100% で指定できます。高品質設定の処理速度、メモリ消費、効果は素材とハードウェアに依存します。

### 出力サイズ

**倍率指定**は 2×、4×、カスタムに対応します。現在の単層超解像は 1 倍より大きく 4 倍以下で、縦横比を維持し偶数寸法にそろえます。**解像度指定**ではプリセットまたは幅・高さを入力できますが、エンジンの縦横比と各軸の拡大率制限は引き続き適用されます。

VSR を複数置くと、前の出力を次の入力として順に拡大します。書き出しで「素材の解像度」を選ぶと、拡大結果を保存前に元の寸法へ戻します。チェーンの最終寸法を残す場合は「処理チェーンの出力」を選んでください。

<a id="truehdr"></a>
## TrueHDR と色

TrueHDR は SDR を HDR10 に変換し、VFX SDK Core と TrueHDR モジュールを必要とします。カードでは**コントラスト、彩度、中間グレー、目標ピーク輝度**と**AI デバンディング**を設定できます。

| パラメーター | 範囲 |
| --- | --- |
| コントラスト / 彩度 | 0–200、デフォルト 100。 |
| 中間グレー | 10–100、デフォルト 50。 |
| 目標ピーク輝度 | 400–2000 nit、デフォルト 650 nit。 |
| AI デバンディング | デフォルトで有効。単独で無効化できます。 |

HDR10 素材にも適用できます。その段階の直前で SDR にマッピングし、新しい HDR 映像を生成します。明るさと色を再解釈する処理であり、**元の HDR を無損失で往復する変換ではありません**。

TrueHDR の入力は RGBA8 SDR です。SDR 10-bit 素材でも、この効果を全工程 10-bit の無損失処理とは呼べません。HDR10 経路は実験的です。HLG、HDR10+、Dolby Vision はここで説明する対応範囲に含まれません。

### プレビューと表示環境で見え方が違う理由

Windows デスクトップ版の動画と TrueHDR 静止画は、ネイティブ FP16/scRGB プレビューに対応します。ディスプレイと Windows HDR の両方を有効にすると HDR 表示になり、無効時は SDR にマッピングします。ファイル比較、通常の画像書き出し、このサイトでは SDR マッピングを使うため、HDR ディスプレイの実際のピーク輝度は再現しません。

<a id="flow"></a>
## オプティカルフローによる誘導

オプティカルフローは再構成段階の動きの誘導に使います。NVIDIA VFG とは別の機能です。VFG は独自のフレーム生成処理を使うため、VFG のためだけに RAFT を計算する必要はありません。

| エンジン | 設定 |
| --- | --- |
| NVIDIA NVOF | NVIDIA のオプティカルフロー API を使い、現行エンジンが提供するプリセットに従って品質を選択します。 |
| AMD FidelityFX Optical Flow | 性能 / 品質の 2 段階。解析はそれぞれ半解像度 / 全解像度ですが、主映像の寸法を下げるわけではありません。 |
| RAFT-Large | 解析長辺の上限は 512 / 720 / 1080。反復回数は独立して調整できます。追加の PyTorch/CUDA と重みが必要です。 |

RAFT の速度・バランス・品質の既定値は**512 / 4 回、720 / 6 回、1080 / 12 回**です。個別設定を行うとそちらが優先されます。解析サイズは動き推定だけに影響し、主映像の処理解像度は変えません。サイズや反復回数を増やすと通常は計算量も増えるため、動く領域で効果を確認してください。

<a id="quality"></a>
## 画質と時間方向の安定化

後処理は**元映像に対するモデルの補正分**を調整します。映像全体へのグローバルな色調整ではなく、NR 強度とも異なります。

| 項目 | 意味 |
| --- | --- |
| 全体 / 残差強度 | モデル出力と元映像との差分を拡大・縮小します。モデル内部の NR 強度とは別です。 |
| 明度 / 色度強度 | 明度と色度の補正を個別に調整します。色度 0 で元映像の色度を維持し、1 でモデルの色度変化を維持します。 |
| 低周波 / 高周波強度 | 大きな範囲の変化と、細部・テクスチャーの補正を別々に調整します。 |
| 色相 / 暗部 / ハイライト保護 | 対応する領域や方向の補正を抑えます。0 はその保護を無効にします。 |
| ソフト圧縮 | 補正の正負方向を保ったまま、過大な補正を弱めます。 |
| 領域保護 | 長方形や楕円内の補正を減らし、境界をぼかせます。自動マスクとは独立です。 |

### 時間安定化とシーン検出

静的な低周波蓄積は、元映像が局所的に安定している部分でのみ過去の残差を混合します。フローによる再投影は行いません。シーク、素材の切り替え、シーン変化で履歴をリセットします。シーン検出だけを使う場合は全解像度の時間履歴を保持しません。

デバッグ表示は残差や保護ウェイトを映像として出力し、GPU 書き出しにも影響する場合があります。本番の書き出し前にデバッグ表示を無効にしてください。

<a id="preview"></a>

読み込み後はモデルを起動せず元素材を表示し、動画のシークでも元フレームを確認できます。HDR 元動画のサムネイルは SDR 表示にマッピングします。チェーンを設定してプレビュー上の **レンダリング開始** を押します。動画は **リアルタイム処理** と **事前レンダリング** を選択可能。事前処理は現在フレームから 5/10 フレーム、0.5/1/2/3/5 秒で、末尾で打ち切ります。完了後は **結果を確認** または緑のキャッシュ表示で動画比較を開きます。書き出し選択範囲は変更せず、設定変更だけでは再処理しません。停止は現在フレームの終了を待ち VRAM を解放。素材変更・再起動・バックエンド復旧後は手動で再度開始します。
## プレビューと範囲選択

ワークベンチには元映像、処理後、中央比較、左右表示があります。中央の境界線は GPU 上に保持した画面を再描画するため、動かすだけならモデルは再実行しません。モデルパラメーターを変えた場合は再処理が必要なことがあります。

### まず短い区間で確認

1. 動画を読み込み、タイムライン下の**選択範囲を書き出し**を有効にします。
2. 両端をドラッグするか、開始・終了フレームを入力します。どちらの境界でも表示位置を調整できます。
3. **選択範囲をプリレンダー**で実際のエンコード動画を作り、最終結果を確認します。
4. 完了し、現在の素材と設定に一致する区間を**緑のバー**で表示します。バーまたは「結果を確認」から比較ページへ進めます。

素材、処理設定、エンコード設定を変更すると、古いキャッシュの緑表示は無効になります。プリレンダーは同じ GPU 書き出しキューを使い、リアルタイムプレビューを一時停止します。範囲書き出しを無効にすると全体を書き出します。

フレーム番号は 1 始まりで、終了フレームを含みます。フレーム指定は固定フレームレートと連続タイムスタンプを要求し、非対応の可変フレームレートや欠落フレームは拒否します。区間先頭では時間履歴をリセットするため、全体の先頭から連続処理した同位置の画面と境界付近が異なる場合があります。

### ステータスバーの見方

- **GPU メモリ**は他のアプリを含むカード全体の使用量で、Lunarc 専有量ではありません。
- **処理 FPS**は直近の処理時間から算出し、初期化、シーク、キャッシュの影響を受けます。
- **表示 FPS**は実際の表示速度で、素材の公称 FPS ではありません。
- **各段階の遅延**は単純加算できる GPU タイムスタンプではありません。キャッシュ、融合、フロー、表示は分けて解釈してください。

<a id="presets"></a>
## プリセット管理

右側の処理順序の上に、プリセット選択と**プリセットを保存**があります。調整後に名前を付けて保存してください。同じ名前で保存すると上書きされます。

管理ページで保存済みプリセットを展開すると、デフォルトから変更した項目、元の値、保存値、変化量を確認できます。NR 強度を 1.00 から 0.70 に変えると、差分 −0.30、割合 −30% と表示します。

- デフォルトが 0 の場合は割合を計算せず、差分だけを表示します。
- スイッチ、スタイル、順序には無意味な割合を付けず、選択肢の変更として表示します。
- 第 2・第 3 層の変更は別々に記録します。
- 適用後に設定を変更すると、選択欄は「現在の設定」になります。
- JSON のインポート・エクスポートでバックアップや移行ができます。

[プリセットの差分デモを試す ↗](https://lunarc-workbench.defaddg-9590.chatgpt.site/ja/#preset-demo)

<a id="images"></a>
## 画像と拡大モデル

PNG、JPEG、BMP、WebP、TIFF、AVIF、HEIC / HEIF、JXR（JPEG XR）を読み込めます。通常画像は 8-bit SDR、完全な BT.2020/PQ タグ付き AVIF と scRGB HDR JXR（fixed/float）はリニア FP16 マスターで処理します。16/32-bit 整数 JXR とその他の高位深 SDR 入力は明示的に拒否されます。アニメーション画像は最初のフレームのみ処理します。

### 単一フレーム処理・VRAM・結果キャッシュ

画像を読み込むと、まず元画像を表示します。**1フレームを処理**を押すまで効果は実行しません。設定変更時の自動処理が必要な場合だけ **リアルタイム処理** を有効にしてください。現在の処理が終わってから最新の要求を処理し、複数チェーンを同時実行しません。

- デフォルトの **省VRAM（各処理を順番に実行）** は、各カードの完全な中間画像をRAMに保存し、そのGPUリソースを解放してから次へ進みます。SDRはRGBA8、HDRは線形FP16で、プレビュー画像への圧縮はしません。転送とモデル再ロードの分だけ遅くなります。
- **高速（チェーン全体を保持）** は、連続調整用にモデルと処理リソースを保持します。VRAM使用量は増えます。
- 解放単位はチェーンのカードです。1枚のNRカード内の多層処理は変更しません。自動タイル化や精度低下は行わず、単一処理だけでもVRAMを超える場合があります。

RAMには **今回と前回の2つ** の原寸結果だけを保持します。3回目の処理成功時に最も古い結果を削除し、バックエンド終了時に消去します。**比較対象 → 前回の結果** で再推論せずに比較できます。異なるサイズは表示用に今回のサイズへ合わせますが、各結果のSDR/HDR解釈と書き出しサイズは保持します。

### 画像を見る

- **Alt + ホイール**：ポインター付近を中心に 25%–800% で拡大・縮小。
- **左ドラッグ**：平行移動。拡大時は通常のホイールで上下に移動。
- **ダブルクリック**：全体表示へ戻る。

表示位置は書き出しサイズに影響しません。ズーム、移動、比較線の操作だけでモデルを再実行することはありません。

### 専用拡大モデル

| モデル | 現在の接続仕様 |
| --- | --- |
| IllustrationJaNai V3 | 4× DAT2。ノイズ除去版 / ディテール版。 |
| AnimeSharp V4 | 2× RCAN 標準版。 |

AI モデル実行環境、画像モデルコンポーネント、個別の重みが必要です。公式配布元からのダウンロードとローカルインポートに対応します。デフォルトは画像全体を FP32 で推論します。任意のタイル処理は文脈や境界結果を変えるため、メモリ不足時に勝手に有効化しません。現在は SDR 入力のみなので TrueHDR より前に配置してください。

### 画像を保存

**画像を書き出し**のデフォルトは **処理済みの結果（形式のみ変換）** です。原寸キャッシュを使い、モデルを再実行しません。同じ素材の今回または前回の結果を選べます。設定変更後は再処理するか、その後の変更を無視して保存済みの結果を書き出すことを明示してください。**再処理して書き出す**ことも可能です。PNG、JPEG、WebP、AVIF、HEIC の選択可否はエンコーダーに依存します。

**出力色**で SDR または HDR を選びます。

- **SDR · sRGB**：PNG、JPEG、WebP、AVIF、HEIC を 8-bit SDR で保存します。TrueHDR の結果は SDR にマッピングします。PNG は無損失と透過に対応し、JPEG は透明部分を白で埋めます。WebP の品質 100 は無損失です。
- **HDR · 10-bit PQ**：処理チェーンで TrueHDR を有効にし、AVIF または HEIC を選びます。処理後の FP16/scRGB を直接 BT.2020/PQ に変換し、SDR 表示マッピングを通さず 10-bit・フルレンジ・4:4:4 で保存します。AVIF には動画処理コンポーネントの 10-bit libaom-av1 と AVIF マルチプレクサ、HEIC には pillow-heif/libheif が必要です。選択肢は実際のコンポーネントに従います。

- **UHDR JPEG**：Display-P3のSDR基底画像とHDRゲインマップを含む`.jpg`を保存します。通常のJPEGビューアーは基底画像を、対応ビューアーはHDRを表示します。透過は非対応で、HDRの結果がある場合のみ選択できます。
- **JXL**：SDRは8-bit sRGB、HDRは16-bit BT.2020/PQ RGBで、透過にも対応します。品質100は入力ピクセルの無損失符号化ですが、それ以前の色域変換と量子化は行われます。

コーデックはアプリの実行環境に独立して配置します。不足時は形式を選択できません。8-bit sRGB JXLは再読み込みできますが、HDR JXL入力は未対応です。UHDR JPEGの読み込みはSDR基底画像のみです。[詳細](../image-codecs.md)。

品質 100 でも HDR RGB の無損失は保証しません。BT.2020 の負の成分と 10000 nit を超える成分はクリップし、その数を保存レポートに記録します。露出の自動正規化や未測定のマスタリング情報の追加は行いません。

対応エンコーダーでは元画像の透過を保持できます。キャッシュ使用時は結果をSDRにマッピングして表示します。再処理して保存した後は元画像のサムネイルを表示する場合もあります。保存ファイルはHDR対応ビューアーで確認してください。**HDR 静止画の再読み込みは未対応です。**

静止画ではフレーム間フロー、時間安定化、VFG を実行せず、動画の一括書き出しキューにも入りません。

<a id="framegen"></a>
## NVIDIA VFG フレーム生成

VFG は並べ替えと個別の無効化ができる処理段階です。**書き出し専用**で、リアルタイムプレビューではスキップし素材の FPS を維持します。最終的な動きは選択範囲をプリレンダーして確認してください。

| 設定 | 用途 |
| --- | --- |
| NVIDIA VFG（固定） | 素材 FPS の 2×–16×で出力。5×–16×は実験的です。 |
| NVIDIA VFG（動的） | 60、120、60000/1001 など、素材より高い目標 FPS を入力し、中間時刻を自動計算します。 |
| 品質 | 低・中・高の VFG モデルモードで、RAFT や NVOF のフロー品質ではありません。 |
| シーン切り替え検出 | カットをまたぐ混合を防ぎます。無効にしても他の段階のシーン検出までは無効化しません。 |

未来フレームがない末尾では最終フレームを保持します。動的モードは等間隔の出力時刻を使い、末尾の丸めによる長さの差は出力 1 フレーム未満です。不均一な入力タイムスタンプは拒否します。

対応する NVIDIA GPU、VFX Core、VideoFrameGeneration モジュールが必要です。素材に既に入った重複フレームや、すべての動きの破綻を修復できるわけではないため、出力を確認してください。

<a id="export"></a>
## 動画書き出しとキュー

### 最終解像度

| 選択肢 | 最終結果 |
| --- | --- |
| 処理チェーンの出力 | チェーン全体の出力寸法を使います。VSR が 8K 出力ならその 8K 寸法で保存します。 |
| 素材の解像度 | 元の素材寸法を使い、拡大結果を保存前に戻します。 |
| 解像度指定 | プリセットまたは指定した幅・高さを使います。 |
| 倍率 | 入力寸法に対し ×2、×0.5、カスタム倍率で計算します。 |

最終寸法とチェーン寸法が違う場合だけ、**書き出し時の縮放アルゴリズム**を表示・実行します。最近傍、バイリニア、バイキュービック、Lanczos 2 は、生成フレームも含めてチェーン全体の後で適用します。

### 10-bit と HDR のエンコード

ネイティブ P010 入力は、現在以下の組み合わせを **MKV** で出力します。

| コーデック | 入力 / 色 | Profile |
| --- | --- | --- |
| HEVC | SDR 10-bit / BT.709 | Main10 |
| HEVC | HDR10 / BT.2020・PQ | Main10 |
| AV1 | SDR 10-bit / BT.709 | Main、10-bit |
| AV1 | HDR10 / BT.2020・PQ | Main、10-bit |

AV1 の 10-bit は Main であり、HEVC の Main10 という名称は使いません。入力の色、コーデック、ランタイムに応じて選択肢を制限し、ハードウェア非対応なら明示的に拒否します。勝手に 8-bit や別エンコーダーへ切り替わることは期待しないでください。

音声、字幕、チャプター、メタデータ、添付ファイルは設定とコンテナーの能力に応じて保持します。元の静的 HDR メタデータは適用可能な場合のみ残します。TrueHDR で生成し直した映像に、元のマスタリング情報を新しい測定値として流用しません。

### キュー管理

1. 出力先、ファイル名、エンコード設定を決め、**キューに追加**します。
2. キューを開始し、進捗、FPS、残り時間の目安を確認します。
3. 実行中のジョブは停止してから削除します。待機、完了、キャンセル、失敗のジョブは削除できます。
4. 失敗時は診断レポートのエラーと設定を保存します。原因を直してから再登録し、同じ無効な要求を繰り返さないでください。

<a id="runtime"></a>
## ランタイム・メモリ・更新

### 必要なコンポーネントを導入

基本実行環境と動画処理コンポーネントから始めます。ネイティブフロー、DLSSNR、GPU デコード・エンコードに PyTorch は不要です。RAFT と専用画像モデルにのみ AI 環境と各モデルの重みが必要です。

DLAA は既定でローカル NGX キャッシュを確認し、VSR、VFG、TrueHDR は対応する VFX ディレクトリーを探します。見つからない、または互換性がない場合は、コンポーネント、実行環境と診断、高度な設定で実際の場所を指定してください。10-bit / HDR エフェクトには対応 API を備えたランタイムが必要です。

### DLSSNR のバージョン管理

DLL / ZIP のローカルインポート、信頼するディレクトリー、版のダウンロード、独立キャッシュに対応します。SHA-256、Windows 署名、発行元、アーキテクチャー、製品、版を検証し、切り替え前に古いプレビューセッションを閉じます。通常の DLSS DLL を DLSSNR として使うことはできません。

原版と既知のコミュニティー版は識別情報を表示します。その他のサードパーティー DLL もインポート後に自動選択でき、同じファイルには「身元不明の DLL」と一度だけ通知します。追加の確認は不要です。ファイル形式とハッシュの検証は維持します。新版では A/B モデルを選び、第 2・第 3 レイヤーでも個別に設定できます。切り替え時は旧パイプラインを閉じてから再構築し、既存プリセットは保持します。

ライブラリはそれぞれのライセンスに従います。コミュニティーの版一覧は NVIDIA の公式配布ではなく、署名が有効でもすべての GPU、解像度、HDR 構成での互換性は保証しません。書き出し中に使用中のランタイムを切り替えたり削除したりすることはできません。

### プレビューの GPU メモリを解放

**プレビューメモリを解放**すると、再生を止め、現在のフレームを待ってからプレビューリソースをアンロードします。設定とディスク上のモデルは残ります。設定を変えても自動再読み込みせず、**プレビューを再開**で読み込み直します。

メモリ不足に近い状態でモデル、寸法、素材、チェーンを切り替える際は、まず古いプレビューを完全解放します。精度・解像度の自動低下や、タイル処理の無断有効化は行いません。SDK 内部のピークは完全には予測できず、メモリ不足を必ず防げるわけではありません。書き出し中にこのボタンで書き出しリソースを解放することはできません。

### ソフトウェア更新

**Lunarc について → ソフトウェア更新**で確認・ダウンロードし、終了してから新しいインストーラーを実行します。通常、コンポーネントとモデルは本体と別に保存されます。更新後も実行環境の診断結果を確認してください。

<a id="troubleshooting"></a>
## よくある質問と制限

### 画像を入れたのに拡大モデルのカードがない場合は？

動画ではなく画像を読み込んだことと、インストール版を確認してください。モデルの入口、実行環境、コンポーネント、重みは別々に準備します。名前が表示されるだけでは重みが導入済みとは限りません。新機能はソース版が先行する場合があります。

### VSR で拡大しても書き出しが元の解像度になる理由は？

書き出しが「素材の解像度」になっていないか確認し、「処理チェーンの出力」で寸法を維持してください。解像度を指定すると保存前に最後のリサイズが入ります。

### TrueHDR のプレビューが白っぽい、明るすぎる場合は？

ワークベンチのネイティブ HDR 表示か、SDR にマッピングされた比較・ウェブ画像かを区別し、Windows HDR の状態を確認してください。通常の SDR 画像で HDR ピーク輝度を直接判断できません。

### VFG を有効にしてもプレビュー FPS が変わらない理由は？

リアルタイムプレビューは VFG をスキップします。選択範囲のプリレンダーか短い書き出しで確認してください。ステータスバーの処理速度も最終ファイルの FPS とは異なります。

### モデル切り替えで GPU メモリが足りなくなる場合は？

先にプレビューメモリを解放し、モデルを切り替えて再開します。他の GPU アプリの負荷を減らし、拡大後の寸法や層数も確認してください。精度・解像度の低下やタイル処理は、速度と画質のバランスを見て自分で選択してください。

### ドライバーで GPU がリセットされた後、連打で復旧しますか？

デバイスリセット後の古いリソースは信頼できません。バックエンドの復旧を待ち、それでも戻らない場合はワークベンチとバックエンドを完全終了して再起動します。同じデバイス喪失による連続エラーを別々の故障と考えず、レポートを保存してください。

### 実験的な機能はどれですか？

HDR10、マルチスケール・データ整合性融合、VFG の 5×–16×には実験的実装が含まれます。HLG、HDR10+、Dolby Vision、非対応コーデック・コンテナー構成は対象外です。任意の GPU で 4K 120 fps のリアルタイム処理を保証するものではありません。

ビルドや検証の記録は[プロジェクト文書](https://github.com/Yukikaze1945/Lunarc-DLSS5#05--文档)を参照してください。サイトのデモは操作例であり、モデル実行や本機の設定変更は行いません。
