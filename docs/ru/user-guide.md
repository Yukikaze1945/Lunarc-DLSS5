# Lunarc · Руководство пользователя

[简体中文](../user-guide.md) · [English](../en/user-guide.md) · [日本語](../ja/user-guide.md) · [Русский](../ru/user-guide.md)

По текущим исходникам. В опубликованном установщике новые функции могут отсутствовать. Доступность зависит от GPU, драйвера и библиотек.

Язык интерфейса выбирается по языку системы. Изменить его можно в разделе «Настройки → Язык интерфейса».

<a id="quickstart"></a>
## Первый запуск

Lunarc обрабатывает видео и изображения локально в Windows. Сначала установите среду выполнения, затем добавьте нужные эффекты. Загружать все модели сразу не обязательно.

1. Скачайте установщик из [GitHub Releases](https://github.com/Yukikaze1945/Lunarc-DLSS5/releases), установите и запустите приложение.
2. По подсказкам первого запуска установите **базовую среду** и **компоненты обработки видео**.
3. Для DLSSNR откройте **Среда и диагностика → Библиотека DLSSNR**, скачайте или импортируйте библиотеку и выберите её для использования. DLAA, VSR, VFG и TrueHDR требуют соответствующих компонентов NVIDIA.
4. Нажмите **Импорт** или перетащите локальное видео либо изображение в рабочую область.
5. Сначала включите один эффект и сравните оригинал с результатом. После проверки добавляйте следующие этапы.
6. Для видео откройте **Экспорт и очередь**, для изображений используйте **Экспорт изображения** в правом верхнем углу.

Установленная версия не требует отдельно устанавливать Python, Node.js или CUDA Toolkit. Для RAFT и отдельных моделей изображений нужна дополнительная среда ИИ-моделей. Если они не используются, её можно не устанавливать.

<a id="pipeline"></a>
## Порядок обработки и переключатели

Цепочка справа выполняется **сверху вниз**. Каждый этап получает результат предыдущего. Изменение порядка может повлиять на изображение, время обработки и расход памяти.

| Элемент | Действие |
| --- | --- |
| Маркер слева | Перетаскивание меняет порядок. Поля ввода и ползунки параметров не запускают перетаскивание карточки. |
| Стрелки вверх / вниз | Перемещают этап на одну позицию. |
| Значок глаза | Временно отключает этап с сохранением параметров и позиции. Повторное нажатие включает его. |
| ＋ / − | Разворачивает и сворачивает параметры. Сворачивание не отключает эффект. |
| Удаление | Убирает этап из текущей цепочки. |

DLAA, DLSSNR, RTX VSR, TrueHDR и NVIDIA VFG используют этот порядок. VSR можно добавлять несколько раз; каждая карточка сохраняет свой режим, качество, силу эффекта и размеры вывода.

Модели после VFG обрабатывают и сгенерированные кадры. Поэтому перенос одной и той же модели до или после генерации меняет объём работы. Универсального порядка для всех материалов нет.

[Попробовать сортировку цепочки ↗](https://lunarc-workbench.defaddg-9590.chatgpt.site/ru/#render-order)

<a id="nr"></a>
## DLSSNR и несколько слоёв

DLSSNR — этап нейросетевой реконструкции. Сначала настройте параметры самой модели, затем решите, нужны ли дополнительные средства управления остаточной коррекцией, цветом и временной стабильностью.

| Параметр | Значение |
| --- | --- |
| Сила NR | Задаёт силу исправлений модели. Большее значение означает более сильное вмешательство, а не гарантированное улучшение качества. |
| Локальный тон | Управляет локальной тональной коррекцией модели. Это не общая экспозиция и не преобразование HDR для дисплея. |
| Локальная структура | Регулирует исправления текстур и локальной структуры. |
| Структура кожи | Управляет коррекцией структуры кожи отдельно от локальной структуры. |
| Автоматическая маска | Использует маску модели. Ручная защита области настраивается отдельно. |
| Коррекция интерфейса NR | Запрашивает обработку текста и элементов интерфейса, но не гарантирует распознавание всех субтитров. |
| Стиль изображения | По умолчанию, Естественный и Кинематографический. Оценивайте изменения на одном и том же кадре. |

### Один, два или три слоя

При **последовательной обработке** второй слой получает выход первого, третий — выход второго. Настраивайте каждый слой отдельно через его параметры: настройки первого слоя не являются общими для всей цепочки.

**Многомасштабное слияние с согласованием данных** — отдельный экспериментальный способ. Решатель объединяет результаты разных масштабов; это не последовательное прохождение слоёв. Размеры, веса и параметры решателя влияют на результат и ресурсы. Само количество слоёв не определяет качество.

### Рабочее разрешение и размер экспорта

Рабочий масштаб меняет размеры, используемые при обработке. Это не просто уменьшение окна предпросмотра. Разрешение на странице экспорта задаёт размеры конечного файла в пикселях; проверяйте эти настройки отдельно.

<a id="dlaa"></a>
## Модели DLAA

На карточке DLAA выберите пресет модели. В текущем интерфейсе доступны **По умолчанию, J, K, L, M** и варианты совместимости **E / F**.

- По умолчанию: выбор выполняет библиотека.
- K: рекомендуемая проектом отправная точка для сравнения DLAA.
- J, L, M: сравнивайте тонкие линии, текст и движущиеся края на своём материале.
- E, F: устаревшие подсказки, которые текущая библиотека может заменить.

Это подсказки выбора модели, а не профили кодирования и не уровни качества VSR. Драйвер или библиотека могут их переопределить. Переключение модели может перезагрузить сеанс, поэтому первое обновление иногда занимает больше времени.

<a id="vsr"></a>
## RTX VSR

Режим обработки, качество, сила эффекта и размер вывода — независимые настройки. Сначала выберите режим, затем проверьте доступные для него параметры.

| Режим | Назначение и вывод |
| --- | --- |
| Стандартное сверхразрешение | Обычное увеличение видео по коэффициенту или целевому разрешению. |
| Сверхразрешение высокого битрейта | Для материалов с относительно небольшими потерями от сжатия. |
| Потоковое сверхразрешение | Нужны совместимые видеокарта и библиотека; текущий режим требует RTX 30-й серии или новее. |
| Шумоподавление | Сохраняет исходные размеры. Слишком сильный эффект может сгладить детали. |
| Устранение размытия | Сохраняет исходные размеры. Может одновременно усилить шум. |
| Бикубическое масштабирование | Обычное изменение размера без ИИ-модели. |

### Качество и сила эффекта

Уровни качества: **Низкое, Среднее, Высокое и Очень высокое**. В потоковом режиме доступны только **Среднее и Очень высокое**. Можно оставить исходную силу эффекта библиотеки или задать 0–100%. Скорость, память и результат высокого качества зависят от материала и оборудования.

### Размер вывода

Режим **по коэффициенту** предлагает 2×, 4× и своё значение. Один этап сверхразрешения сейчас поддерживает коэффициент больше 1 и не выше 4, сохраняет пропорции и выравнивает размеры до чётных. Режим **по разрешению** позволяет выбрать пресет или ширину и высоту, но ограничения движка на пропорции и масштаб по каждой оси сохраняются.

Несколько карточек VSR увеличивают изображение последовательно. Если при экспорте выбрано Разрешение источника, увеличенный результат будет уменьшен обратно перед сохранением. Чтобы сохранить размер цепочки, выберите Выход цепочки обработки.

<a id="truehdr"></a>
## TrueHDR и цвет

TrueHDR преобразует SDR в HDR10. Нужны VFX SDK Core и модуль TrueHDR. На карточке доступны **Контраст, Насыщенность, Средний серый, Целевая пиковая яркость** и **ИИ-устранение полос**.

| Параметр | Диапазон |
| --- | --- |
| Контраст / Насыщенность | 0–200, по умолчанию 100. |
| Средний серый | 10–100, по умолчанию 50. |
| Целевая пиковая яркость | 400–2000 нит, по умолчанию 650 нит. |
| ИИ-устранение полос | Включено по умолчанию, отключается отдельно. |

В TrueHDR можно подать и HDR10-источник: перед этим этапом он преобразуется в SDR, затем создаётся новое HDR-изображение. Это новая интерпретация яркости и цвета, **а не обратимое преобразование исходного HDR без потерь**.

Интерфейс TrueHDR принимает RGBA8 SDR, поэтому даже 10-битный SDR-источник не делает этот эффект сквозной 10-битной обработкой без потерь. Путь HDR10 экспериментальный. HLG, HDR10+ и Dolby Vision не входят в описанную здесь область поддержки.

### Почему предпросмотр может выглядеть иначе?

Настольное приложение Windows поддерживает нативный FP16/scRGB для видео и изображений с TrueHDR. При включённом HDR и в Windows, и на дисплее он отображает HDR; иначе выполняется преобразование в SDR. Сравнение файлов, обычный экспорт изображений и этот сайт используют SDR-преобразование и не передают фактическую пиковую яркость HDR-дисплея.

<a id="flow"></a>
## Оптический поток

Оптический поток помогает учитывать движение на этапе реконструкции. Это отдельная функция, не NVIDIA VFG: VFG использует собственную генерацию кадров. Считать RAFT специально для VFG не требуется.

| Движок | Настройки |
| --- | --- |
| NVIDIA NVOF | Интерфейс оптического потока NVIDIA. Выбор качества соответствует пресетам текущего движка. |
| AMD FidelityFX Optical Flow | Производительность и Качество: анализ в половинном и полном разрешении. Размер основного изображения от этого не уменьшается. |
| RAFT-Large | Максимальная длинная сторона анализа 512 / 720 / 1080. Число итераций настраивается отдельно. Нужны дополнительные PyTorch/CUDA и веса модели. |

Исходные сочетания RAFT для Скорости, Баланса и Качества: **512 / 4 итерации, 720 / 6 итераций, 1080 / 12 итераций**. Отдельные настройки имеют приоритет. Размер анализа влияет только на оценку движения, а не на разрешение основного изображения. Больший размер и больше итераций обычно требуют больше вычислений; оценивайте эффект на движущихся областях.

<a id="quality"></a>
## Качество и временная стабильность

Постобработка управляет **поправкой модели относительно оригинала**. Это не общая цветокоррекция всего кадра, и её нельзя путать с силой NR.

| Настройка | Значение |
| --- | --- |
| Общая сила / сила остаточной коррекции | Масштабирует разницу между результатом модели и оригиналом отдельно от внутренней силы NR. |
| Светлота / цветность | Независимо регулирует поправки светлоты и цветности. Цветность 0 сохраняет цветность оригинала, 1 — изменение модели. |
| Низкие / высокие частоты | Раздельно управляет крупномасштабными изменениями и деталями текстуры. |
| Защита тона / теней / светов | Ограничивает коррекцию в соответствующих областях или направлениях. Ноль отключает защиту. |
| Мягкое сжатие | Ослабляет чрезмерные поправки, сохраняя их положительное или отрицательное направление. |
| Защита области | Уменьшает коррекцию в прямоугольнике или эллипсе с растушёвкой границы. Независима от автоматической маски. |

### Временная стабильность и обнаружение сцен

Статическое накопление низких частот смешивает прошлые остаточные поправки только там, где исходное изображение локально стабильно. Перепроецирование по оптическому потоку не выполняется. Перемотка, смена материала и сцены сбрасывают историю. Одно обнаружение сцен не хранит полноразмерную временную историю.

Отладочный просмотр выводит остаточную коррекцию или веса защиты как изображение и может влиять на GPU-экспорт. Перед финальным экспортом выключите его.

<a id="preview"></a>

После импорта отображается исходник без загрузки моделей; перемотка также показывает исходные кадры. Миниатюры HDR-исходника преобразуются в SDR. Настройте цепочку и нажмите **Начать рендеринг** над предпросмотром. Для видео доступны **Рендеринг в реальном времени** и **Предрендер**. Длина: 5/10 кадров или 0.5/1/2/3/5 секунд с текущего кадра, до конца файла. **Просмотр результата** или зелёная метка открывает сравнение видео. Диапазон экспорта не меняется; правка настроек не запускает предрендер повторно. Остановка ждёт завершения кадра и освобождает видеопамять. После смены файла, перезапуска или восстановления сервера нужен новый ручной запуск.
## Предпросмотр и выбор диапазона

В рабочей области есть оригинал, обработанное изображение, центральное сравнение и два изображения рядом. Разделитель перерисовывает сохранённые кадры GPU и сам по себе не запускает модель заново. Изменение параметров модели может потребовать повторной обработки.

### Сначала обработайте короткий фрагмент

1. Загрузите видео и включите **Экспорт выделения** под шкалой времени.
2. Перетаскивайте обе границы или введите начальный и конечный кадры. Обе границы позволяют перемещаться к нужному кадру.
3. Используйте **Предрендер выделения**, чтобы получить настоящий закодированный клип и оценить конечный результат.
4. **Зелёная полоса** отмечает готовый диапазон, который соответствует текущему материалу и настройкам. Нажмите её или Просмотр результата для открытия сравнения.

Изменение источника, обработки или кодирования убирает зелёную отметку старого кэша. Предрендер использует ту же очередь GPU-экспорта и приостанавливает предпросмотр. Отключите Экспорт выделения, чтобы снова экспортировать весь файл.

Нумерация начинается с 1, конечный кадр включён. Выбор по кадрам требует постоянной частоты и непрерывных временных меток. Неподдерживаемые материалы с переменной частотой или пропусками отклоняются. В начале фрагмента история сбрасывается, поэтому кадры у границ могут отличаться от непрерывной обработки с начала всего видео.

### Строка состояния

- **Память GPU** — использование всей видеокарты, включая другие программы, а не только Lunarc.
- **FPS обработки** рассчитывается по последнему кадру и зависит от инициализации, перемотки и кэша.
- **FPS отображения** — фактическая скорость показа, а не заявленная частота источника.
- **Задержки этапов** нельзя складывать как набор GPU-меток времени. Кэш, слияние, поток и отображение следует оценивать отдельно.

<a id="presets"></a>
## Управление пресетами

Справа над порядком обработки находятся выбор пресета и кнопка **Сохранить пресет**. Сначала настройте параметры, затем задайте имя и сохраните. Существующее имя заменяет старый пресет.

На странице управления разверните пресет, чтобы увидеть отличия от значений по умолчанию: исходное и сохранённое значение, абсолютную и относительную разницу. Для силы NR 1.00 → 0.70 показываются −0.30 и −30%.

- Если исходное значение равно нулю, показывается только абсолютная разница.
- Для переключателей, стилей и порядка отображается смена варианта, а не бессмысленный процент.
- Изменения второго и третьего слоёв записываются отдельно.
- После правки применённого пресета поле показывает Текущие настройки.
- Импорт и экспорт JSON подходят для резервного копирования и переноса.

<a id="images"></a>
## Изображения и модели увеличения

Можно импортировать PNG, JPEG, BMP, WebP, TIFF, AVIF, HEIC / HEIF и JXR (JPEG XR). Обычные изображения обрабатываются в 8-битном SDR; AVIF с полными тегами BT.2020/PQ и scRGB HDR JXR (fixed/float) используют линейный FP16-мастер. 16/32-битные целочисленные JXR и другие SDR-входы высокой разрядности явно отклоняются; у анимированных изображений обрабатывается только первый кадр.

### Один кадр, видеопамять и кэш результатов

После импорта сначала показывается оригинал. Эффекты запускаются кнопкой **Обработать один кадр**. Изменения параметров не запускают обработку автоматически. Для этого включите **Обработку в реальном времени**, а затем отключите её для возврата к ручному режиму. После текущей работы выполняется последний запрос; несколько цепочек одновременно не запускаются.

- По умолчанию включена **Экономия видеопамяти (по этапам)**. Полный промежуточный результат каждого этапа сохраняется в ОЗУ, а его GPU-ресурсы освобождаются до следующего этапа. SDR хранится в RGBA8, HDR — в линейном FP16, без сжатия в картинку предпросмотра. Передача данных и повторная загрузка моделей увеличивают время.
- **Быстро (вся цепочка в памяти)** сохраняет модели и ресурсы для повторной настройки, но требует больше видеопамяти.
- Освобождение выполняется между карточками цепочки. Внутренний многослойный алгоритм NR не меняется. Автоматическое разбиение на плитки и снижение точности не применяются; отдельный этап всё ещё может превысить объём видеопамяти.

В ОЗУ хранятся только **текущий и предыдущий** полноразмерные результаты. Третий успешный рендер удаляет самый старый; закрытие бэкенда очищает кэш. Выберите **Источник сравнения → Предыдущий результат** для сравнения без повторного запуска моделей. Размеры подгоняются к текущему результату только для показа; интерпретация SDR/HDR и размеры экспорта сохраняются.

### Просмотр изображения

- **Alt + колесо**: масштаб 25%–800% относительно области указателя.
- **Перетаскивание левой кнопкой**: сдвиг изображения. При увеличении обычное колесо перемещает его по вертикали.
- **Двойной щелчок**: вписать изображение в область просмотра.

Положение просмотра не меняет размеры экспорта. Увеличение, сдвиг и перемещение разделителя не запускают модель заново.

### Отдельные модели увеличения

| Модель | Текущая интеграция |
| --- | --- |
| IllustrationJaNai V3 | 4× DAT2, варианты шумоподавления и детализации. |
| AnimeSharp V4 | 2× RCAN, стандартный вариант. |

Нужны среда ИИ-моделей, компонент моделей изображений и отдельные веса. Поддерживаются загрузка из источника автора и локальный импорт. По умолчанию используется целое изображение и FP32. Дополнительная обработка плитками меняет контекст и результат на границах и не включается тайно при нехватке памяти. Эти модели пока принимают только SDR; размещайте их до TrueHDR.

### Сохранение

Нажмите **Экспорт изображения**. По умолчанию выбран **Готовый результат (только смена формата)**: используется полноразмерный кэш без повторного запуска моделей. Можно выбрать текущий или предыдущий результат того же исходника. После изменения параметров обработайте изображение заново либо явно разрешите сохранить прежний результат без последующих изменений. Доступен и вариант **Обработать заново и экспортировать**. Форматы PNG, JPEG, WebP, AVIF и HEIC зависят от установленных кодировщиков.

Выберите **Цвет вывода**:

- **SDR · sRGB**: PNG, JPEG, WebP, AVIF или HEIC, 8 бит. Результат TrueHDR преобразуется в SDR. PNG поддерживает сохранение без потерь и прозрачность; JPEG заполняет прозрачные области белым. WebP при качестве 100 сохраняется без потерь.
- **HDR · 10-bit PQ**: включите TrueHDR в цепочке и выберите AVIF или HEIC. Обработанное изображение FP16/scRGB напрямую преобразуется в BT.2020/PQ и сохраняется с глубиной 10 бит, полным диапазоном и 4:4:4, без отображения в SDR. AVIF требует 10-битный libaom-av1 и мультиплексор AVIF из видеокомпонента; HEIC — pillow-heif/libheif. Доступность зависит от установленных компонентов.

- **UHDR JPEG**: файл `.jpg` с SDR-основой Display-P3 и картой усиления HDR. Обычные JPEG-просмотрщики показывают основу, совместимые — восстанавливают HDR. Прозрачность не поддерживается. Доступен только для HDR-результатов.
- **JXL**: 8-битный sRGB для SDR или 16-битный BT.2020/PQ RGB для HDR, с прозрачностью. Качество 100 кодирует входные пиксели без потерь, но не отменяет предыдущие преобразования охвата и квантование.

Кодеки находятся отдельно в среде приложения; при их отсутствии форматы недоступны. 8-битный sRGB JXL можно импортировать повторно. HDR JXL пока не принимается; при импорте UHDR JPEG читается только SDR-основа. [Подробности](../image-codecs.md).

Качество 100 не означает сохранение HDR RGB без потерь. Отрицательные компоненты BT.2020 и значения выше 10000 нит обрезаются; их количество записывается в отчёт. Экспозиция не нормализуется, неизмеренные данные мастеринг-дисплея не добавляются.

Прозрачность исходника сохраняется, если её поддерживает кодировщик. Для кэша показывается миниатюра результата в SDR; после повторной обработки может отображаться исходник. Проверяйте сохранённый файл в HDR-совместимом просмотрщике. **Повторный импорт HDR-изображений пока не поддерживается.**

Для статичных изображений не считаются межкадровый поток и временная стабильность, не выполняется VFG и не используется очередь пакетного экспорта видео.

<a id="framegen"></a>
## Генерация кадров NVIDIA VFG

VFG можно переставлять и отключать отдельно. Он работает при **экспорте**; предпросмотр пропускает его и сохраняет исходную частоту кадров. Чтобы проверить итоговое движение, выполните предрендер выделения.

| Настройка | Использование |
| --- | --- |
| NVIDIA VFG (фиксированный) | Вывод с частотой 2×–16× от исходной. Кратности 5×–16× экспериментальные. |
| NVIDIA VFG (динамический) | Задайте частоту выше исходной, например 60, 120 или 60000/1001. Промежуточные моменты рассчитываются автоматически. |
| Качество | Низкое, Среднее, Высокое — режимы модели VFG, а не качество потока RAFT или NVOF. |
| Обнаружение смены сцены | Предотвращает смешивание между разными планами. Отключение не выключает обнаружение сцен в других этапах. |

В конце, когда будущего кадра нет, последний кадр явно удерживается. Динамический режим использует равномерную временную сетку; погрешность длительности из-за округления меньше одного выходного кадра. Неравномерные исходные временные метки отклоняются.

Нужны поддерживаемая видеокарта NVIDIA, VFX Core и модуль VideoFrameGeneration. Генерация не исправляет уже встроенные в материал дубли кадров и не устраняет все артефакты движения. Проверяйте фактический результат.

<a id="export"></a>
## Экспорт видео и очередь

### Конечное разрешение

| Вариант | Результат |
| --- | --- |
| Выход цепочки обработки | Размер после всех этапов. Если цепочка VSR выдаёт 8K, файл сохраняется с этими размерами. |
| Разрешение источника | Исходные размеры. Увеличенный результат уменьшается обратно перед сохранением. |
| Указанное разрешение | Пресет или заданные ширина и высота. |
| Коэффициент | ×2, ×0.5 или своё значение относительно размеров источника. |

**Алгоритм масштабирования экспорта** появляется и выполняется только при различии конечных размеров и выхода цепочки. Ближайший сосед, билинейный, бикубический и Lanczos 2 применяются после всей цепочки, включая сгенерированные кадры.

### 10-битное и HDR-кодирование

Нативный вход P010 поддерживает следующие комбинации в **MKV**:

| Кодек | Вход / цвет | Профиль |
| --- | --- | --- |
| HEVC | SDR 10-bit / BT.709 | Main10 |
| HEVC | HDR10 / BT.2020, PQ | Main10 |
| AV1 | SDR 10-bit / BT.709 | Main, 10-bit |
| AV1 | HDR10 / BT.2020, PQ | Main, 10-bit |

10-битный AV1 относится к Main; название Main10 от HEVC здесь неприменимо. Интерфейс ограничивает варианты с учётом цвета источника, кодека и библиотеки. При неподдерживаемом оборудовании запрос отклоняется, а не незаметно заменяется на 8 бит или другой кодировщик.

Аудио, субтитры, главы, метаданные и вложения сохраняются по настройкам и возможностям контейнера. Статические HDR-метаданные источника остаются только там, где применимы. После создания нового изображения TrueHDR старые данные мастеринга не выдаются за измерения нового результата.

### Работа с очередью

1. Задайте каталог, имя файла и параметры кодирования, затем нажмите **Добавить в очередь**.
2. Запустите очередь и следите за прогрессом, FPS и оценкой оставшегося времени.
3. Выполняемое задание сначала остановите, затем удаляйте. Ожидающие, завершённые, отменённые и ошибочные задания можно убрать.
4. При ошибке сохраните диагностический отчёт с настройками. Исправьте причину перед повторной отправкой, а не повторяйте один и тот же недопустимый запрос.

<a id="runtime"></a>
## Библиотеки, память и обновления

### Компоненты по необходимости

Начните с базовой среды и видеокомпонентов. Нативный поток, DLSSNR и GPU-декодирование/кодирование не требуют PyTorch. Только RAFT и отдельные модели изображений нуждаются в ИИ-среде и собственных весах.

DLAA по умолчанию проверяет локальный кэш NGX. VSR, VFG и TrueHDR ищут соответствующие каталоги VFX. Если компонент отсутствует или несовместим, укажите реальный путь в Компонентах, Среде и диагностике или расширенных настройках. Для 10-bit / HDR нужна библиотека с соответствующими интерфейсами.

### Версии DLSSNR

Менеджер поддерживает импорт DLL / ZIP, доверенные каталоги, загрузку версий и отдельный кэш. Проверяются SHA-256, подпись Windows, издатель, архитектура, продукт и версия. Перед переключением закрывается старый сеанс предпросмотра. Обычная DLL DLSS не заменяет DLSSNR.

Оригинальные и известные сборки сообщества получают отметку об источнике. Другие сторонние DLL тоже можно импортировать и автоматически выбрать: уведомление «DLL с неизвестным источником» показывается один раз для каждого файла, без подтверждения. Проверки формата и хеша сохраняются. Новые библиотеки предлагают модели A/B отдельно для слоёв 2 и 3. При переключении старая цепочка закрывается перед созданием новой; старые пресеты сохраняются.

Библиотеки сохраняют собственные лицензии. Каталог сообщества — не официальный каталог NVIDIA, а действительная подпись не гарантирует совместимость со всеми GPU, разрешениями и HDR-комбинациями. Во время экспорта нельзя менять или удалять используемую библиотеку.

### Освобождение памяти предпросмотра

Кнопка **Освободить память предпросмотра** приостанавливает воспроизведение, ждёт текущий кадр и выгружает ресурсы. Настройки и модели на диске остаются. Изменение параметров не загружает их автоматически; нажмите **Возобновить предпросмотр**.

Если памяти мало, при смене модели, размеров, материала или цепочки сначала полностью освобождается старый предпросмотр. Защита не понижает точность или разрешение и не включает плитки скрытно. Пики внутренних выделений SDK предсказать полностью нельзя, поэтому ошибки нехватки памяти всё ещё возможны. Во время экспорта эта кнопка не освобождает его ресурсы.

### Обновления

Откройте **О Lunarc → Обновление программы**, проверьте и скачайте новую версию. Выйдите из приложения и запустите установщик. Компоненты и модели обычно хранятся отдельно от основной программы; после обновления снова проверьте диагностику среды.

<a id="troubleshooting"></a>
## Частые вопросы и ограничения

### Почему после импорта изображения нет карточек моделей увеличения?

Проверьте, что загружено изображение, а не видео, и уточните установленную версию. Пункт модели, среда, компонент и веса — отдельные требования. Название модели не означает, что веса уже скачаны. Новые функции могут сначала появляться в сборке из исходников.

### Почему после VSR экспорт остаётся в исходном разрешении?

Проверьте вариант Разрешение источника. Выберите Выход цепочки обработки для сохранения её размера. Указанное разрешение добавляет финальное изменение размера перед сохранением.

### Почему предпросмотр TrueHDR выглядит блеклым или слишком ярким?

Сначала определите, используется ли нативный HDR рабочей области или преобразованное в SDR сравнение/веб-изображение, затем проверьте Windows HDR. Обычная SDR-картинка не показывает пиковую яркость HDR напрямую.

### Почему VFG не меняет FPS предпросмотра?

Предпросмотр пропускает VFG. Для проверки используйте предрендер выделения или короткий экспорт. Скорость обработки в строке состояния тоже не равна частоте кадров конечного файла.

### Что делать при нехватке памяти во время смены модели?

Сначала освободите память предпросмотра, смените модель и возобновите просмотр. Уменьшите нагрузку других GPU-программ, проверьте размеры после увеличения и число слоёв. Решение о понижении точности, разрешения или использовании плиток принимайте с учётом скорости и качества.

### Помогут ли повторные нажатия после сброса GPU драйвером?

После сброса старые ресурсы ненадёжны. Дождитесь восстановления backend. Если оно не помогло, полностью закройте рабочую область и backend, затем перезапустите. Сохраните отчёт: повторные ошибки одного потерянного устройства не обязательно означают разные неисправности.

### Какие функции экспериментальные?

HDR10, многомасштабное слияние с согласованием данных и VFG 5×–16× включают экспериментальные реализации. HLG, HDR10+, Dolby Vision и неподдерживаемые сочетания кодеков и контейнеров сюда не входят. Обработка 4K 120 fps в реальном времени на любой видеокарте не обещается.

Записи о сборке и проверках находятся в [документации проекта](https://github.com/Yukikaze1945/Lunarc-DLSS5#05--文档). Демонстрации на сайте показывают только интерфейс, не запускают модели и не меняют настройки локального приложения.
